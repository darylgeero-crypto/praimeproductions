SFZ FACTS (read directly from "Hang-D-minor 20220330.sfz")
- 1 global (ampeg_release=8), 9 groups, 51 regions, no tune= opcodes.
- Each group is one key with random-region takes (lorand/hirand):
  key 57 (A3, 5 takes), 62 (D4, 7), 64 (E4, 6), 65 (F4, 6), 67 (G4, 6),
  69 (A4, 6), 70 (Bb4, 5), 72 (C5, 5), 74 (D5, 5).
- The README lists C4 among the instrument's notes ("A3, C4, D4, E4, F4,
  G4, A4, Bb4, C5, D5"), but NO C4 sample file exists and NO C4 group is
  in the SFZ — so C4 was NOT used. The SFZ is the instrument definition
  and its mapped range is the 9 keys above (same rule as the ocarina
  run's unused A6.flac).
- README WARNING, followed exactly: "Unlike other sound banks, we
  shouldn't fill missing in-between semitones by varying the pitch of
  nearby notes. When one note of the hang is played, all other notes
  resonate in background, creating a characteristic warm compound sound
  tuned in D minor in this particular case. If the frequency of one note
  is shifted, its background chords would be shifted as well to random
  scales." So the bank is the 9 real notes ONLY — no pitch-shifted
  filler semitones. The other 42 FLACs are random alternates of the same
  9 notes, not separate notes; only the first take (_01) of each note
  was used.

BUILD RECIPE (build_hang.py)
- 9 notes: suite/samples/kits/hang-01..09.ogg
  (note01 = MIDI 57 A3, 02 = 62 D4, 03 = 64 E4, 04 = 65 F4, 05 = 67 G4,
  06 = 69 A4, 07 = 70 Bb4, 08 = 72 C5, 09 = 74 D5).
- From the 9 _01 FLACs; NO pitch shift (see README warning above) and NO
  asetrate step — sources are already 44.1 kHz, so the -147-cent bug
  cannot apply. Stereo downmixed to mono, 44.1 kHz mono OGG q5. No trim.
- Level: per-file gain so each built file peaks at the library -18.5 dB
  target, PLUS a Vorbis-overshoot compensation found and fixed this run:
  the first build (gain = -18.5 - source peak only) decoded at
  -14.78..-15.87 dB — Vorbis q5 overshoots +2.63..+3.72 dB on these
  transient-rich hang hits (a WAV render of the same chain measures
  -18.5 exactly, so the overshoot is in the Vorbis encode, not the gain).
  Each file was rebuilt with an extra cut equal to its own first-build
  decoded overshoot (gains -19.69..-21.47 dB total).
