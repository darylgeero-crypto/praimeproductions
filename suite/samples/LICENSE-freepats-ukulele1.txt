AUTHENTICITY — real recorded tenor ukulele, not synth
- Source: RØDE Podcaster mic, Elgato Wave XLR, captured at 96 kHz / 24-bit
  mono, one room, one session, fixed mic position and gain throughout.
- Processing (per README): resampled 96 kHz -> 48 kHz; 6th-order Butterworth
  high-pass at 190 Hz on the pitched samples (fridge compressor noise at
  105-140 Hz); trimmed to the full natural decay per note (3.25 s at the
  bottom down to 1.10 s at the top); 150 ms fade at each tail; levels
  matched across notes on a 300 ms window from the attack, then one global
  gain (+5.2 dB) so the loudest peak lands at -3 dBFS. Peaks run -3.0 to
  -8.4 dBFS — independently reproduced by this run's probe FFT
  (measure_ukulele.py: peaks -3.00 to -8.38 dBFS), which validates the
  measurement pipeline. The two percussive samples are each scaled to
  -3 dBFS individually.
- The two percussive articulations are part of how a ukulele is actually
  played (per README): body-tap.wav — a knock on the instrument body
  (0.31 s); chuck.wav — a strum into damped strings, the percussive "chk"
  of a muted stroke (0.16 s). Both are included in the PrAIme bank as
  ukulele-tap.ogg / ukulele-chuck.ogg.

BUILD RECIPE (build_ukulele.py)
- 29 pitched notes, MIDI 58-86: suite/samples/kits/ukulele-01..29.ogg
  (note01 = MIDI 58 A#3/Bb3 ... note29 = MIDI 86 D6).
- From the 13 FLACs; ffmpeg asetrate pitch-shift per SFZ zone,
  44.1 kHz mono OGG q5, no trim (longest built note 3.59 s), sources
  already carry a 150 ms tail fade.
- Level: per-source peak measured mono, gain set so each built file peaks
  at -18.5 dBFS (mono sources: volumedetect peak is unambiguous — the
  stereo sum-vs-average 3.01 dB issue from the timpani run does not apply).
- BUG FOUND AND FIXED IN THIS RUN: the first build used
  asetrate=44100*2^(semis/12) on 48 kHz sources, which relabelled the
  samples as 44.1 kHz and pitched every note 147 cents flat while
  stretching durations by 48000/44100 (built durations were 1.0884x the
  sources). The first verify run caught it only as boundary artefacts
  (deviations clustering at the +/-60-cent search edge, 23 of 29 "fail").
  Fix: asetrate=48000*2^(semis/12), then aresample=44100. The verify
  script's search window was also widened to +/-200 cents so a systematic
  error fails loudly instead of clamping to a boundary. NOTE FOR OTHER
  BANKS: the FSBS guitar / bass / sax / accordion banks were built from
  sources at other sample rates — if any of those builds used the same
  wrong-base-rate recipe, those banks may also be flat. Worth a spot
  check on a future run; out of scope here.
